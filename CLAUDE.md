# VOLÀ — working notes for Claude

A static storefront for a denim couture maison. 16 HTML pages, vanilla JS, one
stylesheet. **No build step, no framework, no dependencies, no package.json.**
What is in this directory is what ships. It is a git repo (github.com/asfoursimon1-glitch/Vola),
deployed via classic GitHub Pages serving `main` from the repo root — the 16
HTML pages must stay at root for that to keep working.

Read this first, then the topic doc for whatever you are touching. `README.md`
is long (68KB) — it is a reference, not a preamble. Do not read it whole.

---

## The one rule everything else follows

**Derive facts from data; never assert them in copy.**

A number, a price, a count, a rating, an address, a privacy claim — if it can be
computed from config or data, it must be, so the site cannot contradict itself.
This is not a style preference. It is the reason most of this codebase looks the
way it does, and most of the work in its history was removing a hand-written
fact that had gone stale somewhere else on the site.

Three corollaries, all load-bearing:

1. **Nothing is claimed until a response confirms it.** No "Message sent" before
   the endpoint answers. No "You're subscribed" when the API said 202
   ("accepted"). No success wording chosen by a timer.
2. **Unconfigured degrades to honest, never to fake.** Every integration ships
   blank and must still work — saying plainly that nothing was sent, rather than
   thanking someone for joining a list that does not exist.
3. **User data is destroyed only after confirmed success.** A saved draft
   survives a failed submit. `.catch()` resets nothing.

Before writing any user-facing sentence, ask: *can this go out of date without
anyone noticing?* If yes, compute it.

## Run it

```bash
python serve.py
```

Or via the Browser pane: `preview_start {name: "vola"}` (port 8000, see
`.claude/launch.json`). `serve.py` sends `no-store` — there are no hashed
filenames, so a cached `vola.css` means editing a file and seeing nothing
change. There are no tests and no linter; verification is done in the browser.


`docs/ANALYTICS.md` · `docs/CONSENT.md`. Each covers one integration end to end.

## JavaScript conventions

Every file is `(function () { 'use strict'; … })();` — ES5-flavoured, no
modules, no transpiling, no `let`/arrow-only syntax that would surprise the
rest. Shared state hangs off `window.VOLA`.

**Script order matters and is identical on all 16 pages** (only the folder
prefix differs from the list below — every path is `assets/js/<folder>/<name>`):

```
shopify-config.js  →  consent.js  →  analytics.js  →  data.js  →  app.js  →  [page scripts]
(integrations)        (integrations) (integrations)   (core)      (core)      (pages, + a
                                                                                shared core tail:
                                                                                auth/shopify/
                                                                                newsletter/motion/
                                                                                fit/faq/forms)
```

- `data.js` publishes `VOLA.products` etc. **synchronously at script time** —
  page scripts read it directly, not on DOMContentLoaded.
- `consent.js` and `analytics.js` load *before* `app.js`, so they cannot use
  `V.esc`, `V.toast` or `document.body` at boot. Their APIs are defined
  immediately; only their rendering is deferred to DOMContentLoaded.
- Page scripts go last and are named after the page (`shop.html` → `shop.js`).

`app.js` is the shared layer: cart store, drawer, toasts, nav, reveal, plus
helpers you should reuse rather than reinvent — `V.money`, `V.esc`, `V.icon`,
`V.toast`, `V.announce`, `V.overlay`, `V.formField`, `V.card`, `V.stagger`,
`V.qtyControl`, `V.numberWord`.

**Single sources of truth in `app.js`:** `VOLA.terms` (shipping threshold, flat
rate, returns window) and `VOLA.house` (address, email, phone, hours, reply
promise). These were once written out in nine places. Never restate them in
markup — read them.

## Configuration

`assets/js/integrations/shopify-config.js` is **the only file you edit to connect a
service**. Five services plus the consent layer, all currently blank/off. It has
extensive comments; read them before changing a field.

**Public vs private credentials — this matters.** These are public by design and
correctly ship in the browser: the Shopify **Storefront** token, the Klaviyo
**company ID**, the Formspree endpoint, the Plausible domain.

> **Never put a private credential in this directory.** The Judge.me API token,
> the Shopify **Admin** token, and the Klaviyo **private** key belong in the
> environment and are seen only by the `tools/` scripts:
> `JUDGEME_TOKEN=… node tools/judgeme-sync.mjs`

Build-time vs runtime is decided by exactly that: if the credential is private,
it syncs at build time into `data.js`; if public, it runs in the browser.

## Privacy and consent — do not casually change this

The privacy page does not contain written claims. `assets/js/pages/privacy.js`
computes every one of them from the same config the runtime reads — the storage
table, the processor list, the legal bases, the retention rows, even a DOM scan
for a Google Fonts link. Set `analyticsConfig.storesOnDevice` on a service that
is actually running (`domain` filled) and six things move together, including
four sentences on that page. A service that is off needs no consent, so the
flag alone does nothing — see docs/CONSENT.md.

If you add anything that stores or reads data on the device, or contacts a third
party, **you must** register it — in `KEYS`/`OWNERS`/`processors()` in
`privacy.js`, and in `services()` in `consent.js` with `stores:` and a category.
Otherwise the privacy page becomes a lie, silently, which is the specific
failure this architecture exists to prevent.

**There is no cookie banner, and that is the finished behaviour** — zero
cookies, cookieless analytics, self-hosted fonts, localStorage only for what the
reader asked for. The consent layer is built, derived, and renders nothing until
a service declares `storesOnDevice: true`. Do not "add a cookie banner": it
would be a regression. See `docs/CONSENT.md`.

`privacy.html` is a **draft with six named blanks** (registration number, VAT,
DPO, statutory retention, per-processor transfer mechanisms, a lawyer's review)
and carries a `.devnote` banner saying so. Print a named blank rather than
inventing a legal detail.

## Build-time tools

```bash
node tools/shopify-sync.mjs          # catalogue → data.js
JUDGEME_TOKEN=… node tools/judgeme-sync.mjs   # reviews → data.js  (--dry, --json)
node tools/fonts-fetch.mjs           # woff2 + fonts.css + OFL.txt
```

House rules for these: rewrite **only** the array they own in `data.js`; strip
their own prior banner so reruns are idempotent; **skip rather than guess** when
matching is ambiguous (two candidate products = a warning, not a coin flip); use
`process.exitCode`, never `process.exit()` — it trips a libuv assertion on
Windows here. `tools/fixtures/` holds recorded responses for offline runs
(`JUDGEME_MOCK=`).

## Accessibility

The bar already met, and to be kept: linked error summaries, `aria-invalid`,
`role="status"` / `role="alert"`, deliberate focus management, and AA contrast
**verified programmatically** rather than eyeballed. Also `prefers-reduced-
motion`, visible focus states, and no horizontal scroll at 375px — check that
last one after any change to a wide element; a table needs `.tablewrap`, and a
grid item needs `min-width: 0`.

## Design system

`design-system/vola/MASTER.md` was rewritten on 2026-09-10 from the shipped CSS
and now matches it: the real `--c-*` / `--space-N` token names, the square
`--radius: 0`, the two-accent contrast rule, the actual components (`.btn`,
`.card`, `.input`/`.field`, `.drawer` — there is no centred modal), the 18-icon
hand-drawn set, and the dependency-free motion layer.

**`assets/css/vola.css` is still the source of truth**; MASTER.md describes it.
If they disagree, the CSS is right and MASTER.md has gone stale again — fix it.
A per-page override may be added at `design-system/vola/pages/[page].md`; that
directory exists and is empty.

## Working here

- **Match the surrounding code.** The comment density is unusually high and
  deliberately so: comments explain *why a decision was made*, not what a line
  does. A change that removes the reasoning is a regression.
- **Verify in the browser, don't assert.** Screenshots in this environment time
  out often; fall back to DOM measurement (`read_page`, computed styles,
  bounding rects, `performance.getEntriesByType('resource')`) and say that you
  did.
- **Avoid `node -e` and heredocs in Bash here.** Backticks, `$1` and `\'` get
  interpreted by the shell and have silently corrupted files in this project.
  Use the Edit and Write tools.
- `data.js` still holds **19 hand-written products** (only `REVIEWS` is empty,
  awaiting a sync). The `README.md` section "Content to replace before launch"
  lists what is still placeholder.
